# AGENTS.md — Инженерные правила для ИИ-агентов

Этот файл задаёт технические контракты, ограничения и протокол работы в репозитории `snake_neural_lab`. Пользовательская документация находится в `README.md`.

## 1. Окружение и команды

- **ОС / шелл:** Windows, PowerShell 5.1 (не использовать `&&` — разделять команды через `;` или `; if ($?) { ... }`).
- **Python:** всегда использовать `E:\Code\Projects\snake_neural_lab\venv\Scripts\python.exe` (Python 3.12, `torch` CPU, `numpy`, `numba`; `include-system-site-packages = true` подключён ради глобального `tensorflow` для `Zmey-smart`).
- **Юнит-тесты:**
  ```powershell
  E:\Code\Projects\snake_neural_lab\venv\Scripts\python.exe -m unittest discover -s tests -v
  ```
- **Стенды оценки:** `tests/eval_ppo.py` и `tests/eval_dqn.py` (не начинаются на `test`, поэтому `unittest discover` их не запускает). При однопоточном eval выставлять `torch.set_num_threads(1)`.

## 2. Жёсткие ограничения и инварианты

1. **PPO — строго чистая 1-step политика:**
   - Запрещены lookahead, tree search, MCTS, A*, предрасчитанные гамильтоновы циклы и внешние планировщики.
   - Запрещено расширять окно зрения (`11×11`) «на всё поле» — модель обязана оставаться универсальной на картах `10×10..35×35`.
2. **Неприкосновенные зоны:**
   - **`smart_agent.py`** — не редактировать (ограничение в заголовке файла).
   - **`GLOBAL_SIGNAL_LABELS` (34 сигнала) и `dqn_agent.py`** — не менять и не ломать при доработке PPO. Все PPO-специфичные сигналы добавляются только через `PPO_EXTRA_SIGNAL_LABELS` / `PPO_SIGNAL_LABELS`.
   - **`.runtime/snake_ppo.pt` и `.runtime/snake_dqn.pt`** — никогда не перезаписывать во время экспериментов и A/B-бенчмарков. Открывать только на чтение; временные веса хранить в scratch-директории.
3. **Совместимость чекпоинтов (`arch_signature`):**
   - `ARCH_SIGNATURE` и `PPO_ARCH_SIGNATURE` в `web_backend.py` автоматически строятся из числа сигналов и размеров слоёв. Любое изменение этих параметров делает существующие `.pt`-файлы несовместимыми — заранее предупреждать пользователя.
4. **Единый движок BFS:**
   - Геометрические сигналы (`34` + `3 area_ratio`) и `11×11` эго-карта вычисляются в одном месте — `snake_bfs_numba.py` (вызывается из `snake_env.py`). Не создавать дублирующие Python-копии BFS.
5. **Потокобезопасность `web_backend.py`:**
   - Фоновый воркер PPO (`_ppo_training_loop`) работает под `ppo_worker_lock`. Любые команды, меняющие агента, размер карты, `ppo_multiboard`, режим или сбрасывающие состояние, обязаны выполняться внутри `with self._pause_ppo_worker():`.
   - Граф сети для PPO и showcase-змейка читают неблокирующую копию `agent.inference_net` под `agent._inference_lock` (без захвата `agent_lock`).
   - В режиме **Мульти-поле** завершённые фоновые эпизоды со второстепенных карт обновляют только `board_best_scores[ep_board]` и `best_fill_by_board[ep_board]`, но не попадают в `best_score`, `history`, `episode_counter` и `record_full_episode` активной карты.

## 3. Протокол добавления нового датчика (Feature)

Если требуется добавить новый входной сигнал, синхронно обновить 4 места:
1. `backend_config.py` — зарегистрировать имя в `PPO_EXTRA_SIGNAL_LABELS` (или `GLOBAL_SIGNAL_LABELS`, если для обоих) и короткую метку в `SIGNAL_LABELS`.
2. `snake_bfs_numba.py` и/или `snake_env.py` — рассчитать признак.
3. `snake_lab_app.js` — добавить в нужную группу визуального графа сети.
4. `tests/test_snake_env.py` — проверить форму вектора, конечность значений и инварианты.

## 4. Научный протокол A/B-проверок и архив отклонённых идей

- Любую архитектурную или алгоритмическую гипотезу сначала проверять изолированным A/B-тестом с фиксированным seed (`2026`) на 4 картах: `10×10` (200 игр), `15×15` (25 игр), `20×20` (10 игр), `25×25` zero-shot (6 игр). Внедрять в код только после доказанного улучшения.
- **Уже проверено и отклонено (не предлагать повторно без принципиально новой идеи):**
  - Признаки `revisited` (безусловные и hungry-gated): ломают здоровое следование за хвостом или просаживают `20×20`.
  - `hunger_ratio` как вход, `7ch` multi-scale карта, 3-слойная CNN, 5-й канал `free_degree`.
  - Зеркальная аугментация `Left↔Right` (`DataAug2x` разрушает согласованную спираль; `SymLoss` режет скорость вдвое и просаживает `20×20`).
  - `PPO_NUM_ENVS = 32` (~0% прироста скорости на CPU при вдвое более коротком горизонте rollout).
  - `PPO_GAMMA = 0.997 / 0.998` (проседают `15×15` и `20×20` относительно `0.995`).
  - `bfloat16` на CPU (в ~26× медленнее `fp32` без аппаратного AVX-512 BF16).
  - Прямоугольные поля (`5×10`) в тренере — квадратный мульти-микс `8×10 + 4×15 + 4×20` сам переносится на `5×10` с `96%` побед zero-shot.
  - Запись `.json.gz`-реплеев на диск и старые июльские скрипты `analyzer/` — удалены (внутренний `Failure-Replay` в памяти PPO сохранён).
